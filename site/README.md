# Forever DB: the website

A static site (React 19, Vite 8, TypeScript, Tailwind 4, the same stack as the Rogue Handbook) that browses the dataset in `../data/`: items, spells, builds, what changed in each build, side-by-side version comparison, and which content is still encrypted.

```sh
python3 ../pipeline/site_data.py   # turn ../data into site/public/data (git-ignored, ~63 MB; rerun after the data changes)
npm ci --ignore-scripts            # Node >= 22.12 locally; CI uses Node 26 (see .nvmrc)
npm run dev                        # http://localhost:5173
npm run typecheck && npm test      # types and unit tests
npm run build                      # dist/
```

## What is where

| Path | Purpose |
|---|---|
| `src/pages/` | `Home`, `Browse` (items, spells), `Entity` (item and spell detail), `Builds`, `Build` |
| `src/components/` | `FilterPanels` (shared by browse and build pages), `History` (timeline and compare), `VirtualTable`, `ui` (icons, badges, controls) |
| `src/lib/data.ts` | loads and types the files `pipeline/site_data.py` writes (`../docs/site-data.md`) |
| `src/lib/history.ts` | rebuilds an entry as it was in any past version from its change history; verified against real past scans (`../pipeline/tests/check_history_roundtrip.py`) |
| `src/lib/filters.ts` | every filter and sort, driven by URL query parameters |
| `src/lib/describe.ts`, `format.ts` | readable names for fields, values, slots, schools, effects |
| `src/data/reference.json` | effect/aura/power names, generated by `../scripts/gen_reference.py` |
| `src/config.ts` | site name, icon URL (one function to swap if icons are ever self-hosted), data path |

## Decisions worth knowing

- **Hash routing** (`#/items?q=sword`): works on GitHub Pages with no server rewrites, and every filter lives in the URL so any view can be shared. `base` is `./`, so the same build works under `/forever-db/` or a custom domain.
- **No full dataset in the browser.** Browse pages load a ~450 KB (gzipped) index; a detail page loads one 250-entry shard; a build page loads one file. See `../docs/site-data.md`.
- **Encrypted content is first-class** (`../docs/discovery.md`): a lock on icon and name, a Discovered / Encrypted filter on every list, a notice on detail pages, `discovered` events in history, and locked/unlocked keys on build pages.
- **Icons are hot-linked** from `wow.zamimg.com` by name (`config.iconUrl`), with a placeholder when one fails. The CSP in `vite.config.ts` (a `<meta>` tag; Pages cannot set headers) allows only that origin for images.
- **Spell text is the data pipeline's rendering** (`../docs/tooltips.md`): exact numbers, or the raw template with a note, never guessed.
- **Accessibility:** both colour palettes (dark, light by system setting) were checked for 4.5:1 text contrast; rows are keyboard-focusable; sort headers expose `aria-sort`; the encrypted state is also written as text, never colour alone.
- **Phones:** below 720 px the browse tables keep their key columns (name, slot or school, level).

## Publishing

`.github/workflows/site.yml` builds and tests on every push. It deploys to GitHub Pages only when the repository variable `PAGES_ENABLED` is `true` **and** Settings → Pages → Source is "GitHub Actions". Until then nothing is published. Data PRs from the update workflow merge to `main` and redeploy the site automatically once enabled.

## Known limits

See `../docs/known-limitations.md`. For the site specifically: removed items and spells are not browsable (a build page still names them); filters on a build page use an entity's *current* attributes; the compare view works at the field level (it does not render two tooltips side by side as the game would draw them).
